## Application rules
- Keep revision sheet content in a typed client-safe catalogue separate from the revision page, so study content and source attribution stay consistent across reading and filtering.
- Use the shared logo component and its uploaded asset pointer for site branding; keep a small derived raster favicon in public for browser compatibility.
- Exam patterns, mastery rules, timer and scoring live as pure client-safe modules in src/lib/engine/ and are unit-tested; server functions in src/lib/engine.functions.ts reuse them so scoring is deterministic and computed only on the server.
- Answer keys are hidden from students by column-level grants on questions; attempts are written only by server functions using the admin client after auth, so students cannot alter scores.
- The development question bank is generated by scripts/seed-questions.ts (computed numerical keys plus hand-written conceptual items).
- The AI hint tutor streams from the server route /api/tutor (src/lib/tutor.server.ts), verifies the student's session and refuses mock-test attempts, so hints never leak into timed exams and keys stay server-side.
- Option order is shuffled per attempt on the server with a deterministic seed while option ids stay fixed, so scoring and resume are unaffected.
- The extra NCERT bank lives in scripts/data/ncert-bank-2026.sql (AI-assisted drafts, labelled as pending teacher review in their source).
- Admin access uses public.user_roles + has_role(); admin server functions in src/lib/admin.functions.ts verify the role then use the admin client, and every imported or AI-generated question is saved as draft so nothing reaches students until an admin verifies it.
